Retrieval has done its job: a few relevant chunks are ready. The last step is generation, where the model reads those chunks and writes the answer. The shift matters. The model is not being asked what it knows. It is being asked to answer from the text in front of it. That is the point of grounding.

Assembling the prompt

The retrieved chunks are placed into the prompt, each marked with its source. The user's question follows. Order and labels matter. The model needs to tell the passages apart and know which source each one belongs to, so it attributes claims correctly. This step is plumbing, but poor formatting here leads to vague answers and weak citations later.

Answer only from the context

The core instruction is a constraint: answer using only the supplied excerpts, and do not fall back on general knowledge. Without that constraint, the model blends retrieved facts with training data, and the answer is no longer grounded in the sources you provided. With the constraint, the answer stays tied to text you control and check. It also keeps the system aligned with updates: the model reflects the current source text, not stale training data.

Citations and "I don't know"

Two behaviours separate a trustworthy RAG answer from a plausible one. The first is citations. Each chunk carries a source, so the answer should point to the passage behind each important claim. That lets the reader verify the answer instead of trusting the model.

The second is the ability to decline. If the retrieved text does not contain the answer, the right response is to say so. A system that admits the answer is missing is easier to trust than one that fills the gap with a confident guess. In RAG, a safe failure is better than a polished wrong answer.

The model is the last mile

It is tempting to think a stronger model fixes a weak RAG system. It does not. If retrieval hands over the wrong chunks, a stronger model writes a more convincing wrong answer. Generation only works with the context it receives, so the main leverage stays upstream in chunking, embeddings, and retrieval. A good generation step is mostly about discipline: use the context, cite it, and stop when the answer is not there.
