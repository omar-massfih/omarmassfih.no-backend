Retrieval has done its job: a handful of relevant chunks are in hand. The last step is generation, where the model reads those chunks and writes the answer. The shift here is important. The model is not being asked what it knows. It is being asked to answer from the text in front of it, which is the whole point of grounding.

Assembling the prompt

The retrieved chunks are placed into the prompt, usually in a system message, each marked with where it came from. The user's question follows. Order and labelling matter: the model needs to tell the passages apart and know which source each one belongs to, so it can attribute claims correctly. This assembly step is plumbing, but sloppy formatting here shows up as vague or mis-cited answers later.

Answer only from the context

The core instruction is a constraint: answer using only the supplied excerpts, and do not fall back on general knowledge. Without it, the model blends retrieved facts with half-remembered training data, and you lose the guarantee that made RAG worth building. With it, the answer stays tied to sources you control and can check. This is also what keeps the system honest when the store is updated: the model reflects the current text, not a stale memory.

Citations and "I don't know"

Two behaviours separate a trustworthy RAG answer from a plausible one. First, citations: because each chunk carries its source, the model can point at exactly which passage backs each claim, and the reader can verify it. Second, the ability to decline. If the retrieved text does not contain the answer, the right response is to say so, not to invent one. A model told to only use the context and to admit when the answer is not there fails loudly instead of confidently, which is the safer failure.

The model is the last mile

It is tempting to think a better model fixes a weak RAG system. It does not. If retrieval hands over the wrong chunks, a smarter model just writes a more convincing wrong answer. Generation can only work with what it is given, so the leverage stays upstream in chunking, embeddings, and retrieval. A good generation step is mostly about discipline: use the context, cite it, and know when to stop.
