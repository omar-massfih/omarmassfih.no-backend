Retrieval runs every time someone asks a question. The chunks are already embedded and stored. Now the system has to take the question, find the passages most likely to answer it, and pass those passages to the model. This is where a RAG system often succeeds or fails, because the model only has the text it receives.

Embed the query, find the neighbours

The question is embedded with the same model used for the chunks. This produces a query vector in the same space as the stored chunk vectors. Retrieval then finds the stored vectors closest to the query vector and ranks them by distance. In a small store, this might be a full scan over all chunks. In a large store, it usually uses an approximate nearest-neighbour index, which trades a little accuracy for much faster search. Either way, the result is the same: the chunks whose meaning is closest to the question.

Choosing top-k

You do not send every matching chunk to the model. You send the top k closest chunks. Choosing k is a trade-off. Too few chunks, and you risk missing the passage with the answer because it ranked just below the cutoff. Too many chunks, and you fill the prompt with loosely related text. That makes the useful part harder to find and increases token cost. A few strong chunks usually beat a long list of weak ones.

Recall versus precision

The top-k choice is really a balance between recall and precision. Recall means the answer appears somewhere in the retrieved chunks. Precision means the retrieved chunks are mostly relevant. Raising k usually improves recall, because the model sees more candidates. It also lowers precision, because more unrelated text enters the prompt.

RAG usually favors recall first. A useful chunk does nothing if the model never sees it. After retrieval gets the likely answer into the candidate set, the next goal is to improve precision without losing the answer.

When plain similarity is not enough

Nearest-neighbour search finds text with similar meaning, but similar text is not always the best answer. Two common fixes improve the first result. Reranking takes the top candidates and uses a stronger model to sort them by relevance to the question. This helps when the closest vector is related but not useful enough.

Another fix is to bring in connected material. The system might follow tags, links, sections, or document structure to include nearby context. This helps when the answer uses different words from the question, or when one chunk only makes sense together with another. Both approaches start from the same nearest-neighbour result and improve what reaches the model.
