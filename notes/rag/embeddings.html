Keyword search matches words. It misses cases where different words mean the same thing, like "car" and "automobile". It also struggles when the same word has different meanings, like "bank". RAG needs search by meaning, and embeddings are what make that possible. An embedding is a vector: a list of numbers produced by a model trained to place text with similar meaning close together.

Meaning as geometry

The trick is to turn meaning into distance. An embedding model reads a piece of text and outputs a fixed-length vector, often hundreds or thousands of numbers. Text about the same idea ends up nearby. Unrelated text ends up farther away. Once meaning is represented this way, finding relevant text becomes finding the nearest vectors.

Measuring closeness

Search needs a way to measure closeness. A common choice is cosine similarity, which compares the direction two vectors point, rather than their length. Two pieces of text about the same topic should point in a similar direction, even when one is a sentence and the other is a paragraph. Cosine distance is one minus cosine similarity, so smaller distance means the texts are more alike. Vector search sorts results by this distance. 

select text,
       vector_distance_cos(embedding, vector32(?)) as distance
from note_chunks
order by distance
limit ?

Same model on both sides

A vector only has meaning inside the space created by the model that made it. Vectors from two different embedding models should not be compared, because each model arranges meaning in its own space. This has a practical consequence: the same model must embed both the stored chunks and the query at search time.

Changing the embedding model also means rebuilding the vector store. Every stored chunk needs a new embedding from the new model before search works correctly again.

Embeddings are not understanding

An embedding captures similarity, not truth or logic. A wrong passage might still land near the question if it discusses the same topic. Embeddings tell you what looks relevant. They do not tell you what is correct. That is why retrieval quality needs measurement, and why the generation step is still told to answer only from the text it receives.
